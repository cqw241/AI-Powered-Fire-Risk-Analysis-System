# v1.3 相关处罚规定关联

## 目标

在现有“视觉 Finding → Issue Code → 实体法规条款”的确定性链路之后，增加一层确定性的法律责任条款关联。

本版本不做处罚预测，不计算具体处罚金额，不由模型生成处罚结论。页面仅在已经命中实体法规条款时，补充展示经人工核验的国家级相关处罚规定原文。

## 边界

- Qwen 输出保持不变，仍只负责视觉 Finding 和受控 Issue Code。
- 处罚规定不参与视觉判断，也不反向改变 Finding 的风险等级。
- `clause_text` 保存核验后的法规原文，不保存 AI 改写。
- 金额属于法规原文的一部分，原样保留；系统不根据图片计算或预测具体罚款。
- 页面明确提示：相关处罚规定展示不构成违法认定或处罚决定。
- 地方性法规、地方政府规章和地方裁量基准不在本版本范围内。

## 数据结构

新增独立 Risk Pack：

```text
data/legal/risk_packs/cn-mainland-penalties/
├── manifest.json
├── issue_codes.json
├── rule_bindings.json
└── clauses.json
```

该包不新增 Issue Code。`rule_bindings.json` 在原有 `bindings` 之外增加 `penalty_bindings`，每条处罚绑定同时指定：

- `issue_code`：必须是已经受控的现有 Issue Code；
- `legal_clause_id`：必须是已经命中的实体法规条款；
- `penalty_clause_id`：对应的法律责任条款；
- `missing_conditions`：处罚条款相对实体条款新增的适用前提，例如“责令改正后拒不改正”。

这样处罚关系以 `Issue Code + 实体条款` 为键，而不是简单建立“实体条款 → 处罚条款”的全局映射，避免同一实体条款覆盖多个不同违法行为时出现错误处罚关联。

## UI

实体法规条款仍按现有方式展示。若该条款存在处罚关联，则在其后增加“相关处罚规定”，展示：

- 法规名称；
- 条款号；
- 处罚规定原文；
- 处罚层额外需要确认的适用条件。

页面固定显示提示：

> 仅作相关法律责任条款展示，不构成违法认定或处罚决定；是否满足处罚条件及具体行政处理，由有权机关结合现场事实依法认定。

## 核验来源

- 《中华人民共和国消防法》第六十条、第六十一条、第六十二条、第六十三条、第六十六条：国家消防救援局公开现行文本。
- 《高层民用建筑消防安全管理规定》第四十七条第七项：中华人民共和国应急管理部令第5号公开文本。

处罚条款的 `verified_at`、`verification_source` 和 `engineering_note` 均随数据保存，后续法规更新时按现有 Risk Pack 审核流程复核。
