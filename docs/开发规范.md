# 消防风险分析系统开发规范

**适用范围**：本仓库所有功能、修复、测试、Prompt、Schema、法规数据、UI 和文档变更  
**关联流程**：`docs/开发文档.md`  
**编制日期**：2026-08-24

## 1. 协作原则

1. 每个 feature 使用独立分支，分支名使用 `feature/Fxx-short-description`；分支应从最新 `main` 创建。
2. task 与 commit 按实际开发粒度组织，不强制“一 Task 一 Commit”；可以合并相关 task，也可以拆分较大 task。
3. worklog 是可选的协作记录。复杂功能、实验或需要交接时，可使用 `docs/worklogs/_template.md`，不要求每个分支创建或更新 worklog。
4. PR 是 feature 分支的默认集成路径。PR 应说明目标、范围、验证结果和已知限制；自动 Review 或 CI 的具体配置由仓库协作设置决定。
5. MVP 验收以端到端行为为核心：图片上传后，图片处理、Qwen 分析、结构化校验、规则关联、结果组装和 UI 展示必须正确连通。

## 2. 分支与提交

推荐分支流程：

~~~bash
git switch main
git pull --ff-only origin main
git switch -c feature/F04-legal-rules
~~~

commit 应按逻辑完整、便于审查和回滚的粒度组织。commit message 建议使用：

~~~text
<type>(Fxx): <summary>
~~~

常用 type：`feat`、`fix`、`test`、`docs`、`chore`、`refactor`。不得提交密钥、敏感图片、无关临时文件或无功能空提交。

## 3. 端到端行为边界

- Qwen 负责视觉事实、Finding、Evidence、限制和 Issue Code 建议，不输出法规名称、条款号、原文或违法结论。
- 法规名称、条款号、原文、关联关系和缺失条件必须来自 `data/legal/*.json`。
- unknown context（例如场所用途、法定区域、距离、尺寸、审批或维护记录无法从图片确认）应写入 `limitations` 或 `missing_conditions`，不得因此删除或阻止 Finding。
- 无有效 Issue Code 或无 Rule Binding 的 Finding 仍然保留，法规列表可以为空。
- conditional Rule Binding 不能因为条件未知而被丢弃；必须继续输出法规信息、`relation: "conditional"` 和 `missing_conditions`。
- UI 只渲染 `AnalysisResult`，不重新推断法规或修改 Finding 事实。

## 4. F04 规则验收

F04 至少验证：

- Issue Code 白名单过滤不会删除开放 Finding；
- direct 与 conditional 按既定顺序排序并去重；
- conditional Binding 即使存在 unknown context，也会返回对应 Clause 的法规名称、条款号、原文、`relation` 和 `missing_conditions`；
- 无 Binding 时保留 Finding，法规为空且流程不报错；
- 法规字段只来自本地 Clause 数据。

## 5. F05 Pipeline/UI 验收

F05 至少验证：

- `image → Qwen → validation → issue code → rule binding → clause → AnalysisResult → UI` 链路可运行；
- Finding 不因 unknown context、无有效 Code 或无 Rule Binding 被丢弃；
- conditional 关联在结果和页面中同时显示法规与 `missing_conditions`；
- 图片不可用、模型失败、Structured Output 无效等状态可区分；
- UI 能展示图片标注、Finding、证据、优先级、法规、缺失条件、整改建议和限制。

## 6. F06 端到端验收

验收重点不是 Git 历史、commit 数量或 worklog 完整性，而是链路是否正确跑通。至少使用以下场景验证：

- 通道堆物；
- 消火栓或灭火器遮挡；
- 明火或吸烟；
- 电气线路与可燃物；
- 无明显风险图片。

每个场景应确认：输入成功、模型结果可解析、Finding 保留、bbox/证据正确、规则关联符合 direct/conditional 语义、conditional 输出法规和 `missing_conditions`，最终 UI 可见。
