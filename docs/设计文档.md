# 系统设计与行为边界

本系统从单张消防或电气安全场景图片提取可见事实，由本地规则包确定性地关联法规。页面只展示分析结果，不作违法认定。当前实现使用 Qwen3.8-27B、Python 3.13 和 Gradio；运行方式见项目 [README](../README.md)。

## 处理流程

```mermaid
flowchart LR
  A[上传图片] --> B[解码与 EXIF 修正]
  B --> C[Qwen 视觉分析]
  C --> D[结构化校验与清理]
  D --> E[Issue Code 与规则包关联]
  E --> F[AnalysisResult]
  F --> G[标注图与结果页面]
```

| 阶段 | 实现 | 主要职责 |
| --- | --- | --- |
| 图片 | `image.py` | 支持 JPEG、PNG、WEBP；统一模型输入和标注图的坐标基准；转换 0–1000 bbox |
| 模型 | `qwen.py`、`prompts/visual_investigator.md` | 一次分析发送一次请求，返回 `VisualInvestigation` |
| 契约 | `schemas.py`、`schemas/*.json` | 校验模型输出和最终 `AnalysisResult` |
| 法规 | `risk_packs.py`、`rules.py` | 加载启用规则包，过滤 Issue Code，关联条款和整改建议 |
| 编排 | `pipeline.py` | 清理视觉结果，组装状态、Finding 和法规关联 |
| 页面 | `ui.py` | 绘制 bbox，渲染 `AnalysisResult` 与诊断信息 |

## 视觉结果

模型只输出场景概述、区域、Finding、证据、限制和建议的 Issue Code；不得生成法规名称、条款号、原文或违法结论。具体字段以 `schemas/visual_investigation.schema.json` 和 `src/fire_safety/schemas.py` 为准。

- bbox 是 `[x_min, y_min, x_max, y_max]`，坐标为 0–1000 整数。类型或范围不合法属于无效模型输出；反转或零面积 region 在后续清理时删除，并同步清理证据引用。
- 每个 Finding 必须有可见证据。单个无效 region 或 bbox 不应删除整个 Finding。
- 模型可发现 Issue Code 列表之外的风险。未知 Code 被过滤后，Finding 仍保留，法规列表可为空。
- 场所用途、法定区域、真实尺寸、审批和维护记录等图片无法确认的事实，应写入 `limitations` 或法规的 `missing_conditions`；不得据此删除 Finding。

## 规则包与法规关联

运行时扫描 `data/legal/risk_packs/` 的直接子目录。每个包包含 `manifest.json`、`clauses.json`、`issue_codes.json` 和 `rule_bindings.json`；只加载启用的规则数据。条款原文、核验信息和工程注释以各包的 `clauses.json` 为唯一数据源。

Issue Code 经过白名单过滤，再经 Rule Binding 找到有效 Clause。每个 Finding 最多返回三条实体法规，`direct` 优先于 `conditional`，其次按 `priority` 升序排序，同一 `clause_id` 去重。`conditional` 仍返回完整条款，并明确列出需要现场核实的条件。无有效 Code 或无 Binding 时，Finding 保留，`rule_status` 与 `rule_warnings` 说明原因。

`cn-mainland-penalties` 规则包在已选中的实体条款上附加相关处罚规定。绑定键同时包含 Issue Code 和实体条款 ID；处罚条件单独列出。系统不根据图片预测处罚对象、金额或行政处理结论。规则扩展的历史依据分别记录在 [v1.1 法规扩展](v1.1-法规扩展.md) 和 [v1.3 处罚规定关联](v1.3-处罚规定关联.md)。

## 最终结果与页面

最终结构以 `schemas/analysis_result.schema.json` 为准，完整样例见 `examples/analysis_result.example.json`。页面按结果中的顺序展示 Finding、风险优先级、证据、相关法规、缺失条件、整改建议和限制；对应区域在原图上标注编号。页面不重新推断事实、法规或风险等级。动态文本在拼接 HTML 前转义；具体展示原则见 [UI 设计](ui-design.md)。

| `status` | 含义 |
| --- | --- |
| `completed` | 至少一个 Finding，正常展示结果 |
| `no_findings` | 可见范围内未发现明确风险，不代表现场无风险 |
| `image_unusable` | 图片不可解码或不受支持 |
| `model_failed` | 配置、本地规则目录或模型请求失败 |
| `invalid_model_output` | 模型结构化结果无法解析或违反契约 |

一次分析的耗时、模型输出原文和调用日志用于核查模型与后续处理的差异，不改变最终风险判断。
