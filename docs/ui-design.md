# 结果页面设计原则

页面是单图检查报告：先看图定位，再阅读风险证据、相关法规和整改建议。`src/fire_safety/ui.py` 实现页面，`AnalysisResult` 是唯一的业务数据输入。

## 信息顺序

- 左侧上传原图、触发分析并查看带编号的标注图；右侧展示状态和 Finding 列表。窄屏时按图、风险、法规、建议的顺序纵向排列。
- 标注图上的 F1、F2 等编号与 Finding 卡片编号对应。卡片按结果顺序展示，不在 UI 中重新排序、聚合或推断风险。
- 每张卡片展示标题、优先级、可见证据、风险说明、相关法规、整改建议和限制。空的限制或规则提示区块不渲染。
- 法规原文置于可展开区域；`direct` 与 `conditional` 用文字标签和不同视觉样式区分。`conditional` 的 `missing_conditions` 始终可见。
- 若附有相关处罚规定，页面展示原文、额外适用条件及“并非违法认定或处罚决定”的提示。

## 状态与反馈

- 初始状态说明上传与分析操作；`no_findings` 明确结果只基于图片可见范围。
- 加载区依次显示六个视觉阶段，每阶段 2 秒；这些阶段是等待反馈，不代表真实 Pipeline 进度。实际耗时另有独立面板。
- 图片不可用、模型失败和模型输出无效分别显示可理解的错误及重试提示，保留可用的输入图片。
- 结果中的动态文本先经 HTML 转义。错误状态使用可被辅助技术识别的提示；风险标签同时使用文字和颜色。

字体、颜色、间距、组件参数和动画细节以 `src/fire_safety/ui.py` 为准。页面使用本地系统字体，不依赖在线字体服务。
